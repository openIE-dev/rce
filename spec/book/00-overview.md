# RCE Language Specification, draft 0.9: Overview

**Abstract.** RCE is a small programming language whose programs mean one
thing everywhere. A program is turned into a *Form*: a state machine given
by its states, its events, a step function that maps a state and an event to
a new state and an outcome, and the log of events. Every runtime that runs
the Form must produce the same results bit for bit, and the rules that make
this so are checked by machine.

![RCE overview: source, checker, Form P = (S, E, delta, D, lambda), log D, emit targets, host, fabrics](https://raw.githubusercontent.com/openIE-dev/rce/main/docs/figures/rce-overview.svg)

*Figure (informative). The pipeline from source to Form, log, emit targets and host. Source: [docs/figures](https://github.com/openIE-dev/rce/tree/main/docs/figures).*

Three plain points:

1. **Same answer on every target.** Arithmetic, text, floats and concurrency
   have one defined meaning; there is no undefined behaviour.
2. **Every program ends.** Loops, recursion and iterators are bounded, so the
   step function always returns.
3. **Memory is safe by construction.** Ownership, second-class borrows,
   regions and linear handles rule out use-after-free and data races.

Tiny example (a counter that refuses to go negative):

```
state Counter
    n: i64 = 0
event Dec
step Counter on Dec
    check n > 0
    n -= 1
```

**Status.** Draft 0.9, 2026-10-17. Status: for review. Appendix F
is *specified and implemented in part* (F.12) and applies the 2025+ language survey and the security study (transactional
calls, contracts, ghost code, written termination measures, information-flow
labels with robust declassification, a `World` capability, caretaker
revocation, typed shell and prompt output, constant-time functions, declared
budgets, hash-pinned builds, templates, `if let`, trait laws and lexical
hygiene), and states as non-goals the four constructs that would break a
theorem (effect handlers, switchable contracts, mutable aliasing across
`par`, runtime reflection). The reference checker implements a part of it
(Tier 0 hygiene, `World`, definition hashes with `rce api-diff`, transactional
calls; F.12 lists the rest, which it refuses as reserved, not implemented), the Lean files, the
emitters and the tree-sitter port do not, and every theorem it adds
(T42 to T56) is stated and unproved (F.9). There is one language: this text. Drafts 0.5 to 0.9 are
labels of past commits of it, not alternatives; `# rce-version:` is a release label that is
tolerated, ignored and not hashed (2.7), and a label names exactly one spec commit (C.15). The
language of this text is what the reference checker and the Lean files enforce and prove for concurrency
(Appendix C), and a program that an earlier commit accepted may be refused by this one when a rule was
added; an implementation of a release implements that release's text. The core is mechanized in Lean 4
(`spec/lean/`, section 8), a reference type and well-formedness checker
(`spec/checker/`, `rce-check`) implements sections 4, 5 and 7 including the
admission gate of 6.9 (examples, checks, comptime and constants are evaluated),
`tree-sitter/` is a tree-sitter port of the grammar checked against
the LALR(1) tables of section 3, and grammar-level random programs are checked by
`rce-fuzz` (`spec/checker/`). The production compiler has
not been built from this document yet. Changes made while mechanizing are
listed in 9.1 to 9.4. Draft 0.4 follows the language review in
`spec/LANGUAGE-REVIEW.md`; draft 0.5 applies the changes that review
proposed and draft 0.4 deferred (9.4). The changes per draft are in 9.1 to
9.7, and the decisions taken for draft 0.9 by derivation, with the open
questions each closed, are in 9.7 and 9.8.

RCE is defined by this document. A program is a text; its meaning is a Form
P = (S, E, δ, D, λ) (section 6). Runtimes, emitters, harnesses and editors are
not part of the language: they are implementations, and an implementation
conforms when it accepts exactly the programs this document accepts and gives
each one the meaning this document gives it.

**Document status.** This specification is the only normative text.
`SURFACE.md` (the native surface design) and `FORM.md` (the compiler
notes) are informative: two normative texts with two grammars could
disagree, and only one of them is checked by machine. Their programs
must still be accepted by the reference checker. The Form signature is
6.1.

The normative grammar is section 3, and it is also the machine-readable one:
`rce-spec-check` (in `spec/checker/`, Rust only) reads the EBNF of section 3
from `book/03-syntax.md`, builds its LALR(1) tables and fails on any
shift/reduce or reduce/reduce conflict, then parses every program in
`spec/examples/` and requires every program in `spec/examples/reject/` to be
refused, by the LALR(1) tables, the Rust parser and the tree-sitter port
alike, then runs `rce-check` over the same files (all examples together
form one program and must be accepted; the 12 syntax rejects, the 48
programs in `spec/examples/ill_typed/` and the 16 in
`spec/examples/inadmissible/` must be refused). Current result (draft 0.9,
the printed output of `rce-spec-check`, compared with this text by
`scripts/claim-counts.py --check`): the section-3 grammar has 0 conflicts
(100 rules, 491 productions, 974 states); with the additions of C.2,
0 conflicts (114 rules, 560 productions, 1152 states);
with C.2 and F.13, 0 conflicts (119 rules, 588 productions,
1214 states), accepting the 15 Appendix F examples; grammar 62/62 accepted,
12/12 refused; checker 62/62 accepted, 12/12 and 64/64 refused (16 of them
inadmissible). Until 2026-10-12 the same grammar was kept as
`spec/rce.lark` and checked with Lark (0 conflicts, 533 rules in Lark's
expansion); that file is retired.
`rce-fuzz N SEED` generates random type-directed programs from the
grammar's productions, with targeted near-misses. 100,000-program run
(8 parts × 12,500, seeds 1001–1008, `spec/fuzz/RESULTS.md`, with the former
Python generator and Lark): all 100,000
parsed by LALR(1), exactly one Earley parse each, all accepted by
`rce-check`; 516,012/516,012 rule near-misses and 392,362/392,362 syntax
near-misses refused; 0 failures. That run used the draft 0.4 generator.
From draft 0.5 the generator also covers extern, arena bound, structural
recursion, f32, lane-wise arrays, device regions, byte text, u64, select,
linear structs, LOOP_LIMIT and iterators; a 1,000-program run (seed 2026)
of it has 0 failures. The Rust generator, with the section-3 LALR(1)
tables as a third parser: 1,000 programs (seed 7), 0 failures, tree-sitter
and LALR(1) agree on all 4,977 syntax mutants.
